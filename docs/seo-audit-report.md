# تقرير تدقيق SEO والظهور — alsahmm.com

**تاريخ الفحص:** 27 أغسطس 2026  
**النطاق المفحوص:** النسخة الحية `https://alsahmm.com` + مصدر المشروع + نسخة البناء المحلي

## الخلاصة التنفيذية

المشروع يملك أساساً تقنياً جيداً لمحركات البحث:

- الصفحات العامة المهمة تُرسل HTML فعلياً من الخادم/البناء المسبق، وليست واجهة JavaScript فارغة فقط.
- الصفحات المفحوصة تحتوي على عنوان ووصف و`canonical` و`H1` باللغة العربية.
- `robots.txt` متاح بصيغة صحيحة، والنسخة الحية تعيد `200`.
- الصفحة الرئيسية تحتوي على JSON-LD للمنشأة المحلية والموقع والأسئلة الشائعة والعروض والتقييم.
- تم فحص 24 مساراً حياً، وجميعها أعادت `200` في الفحص العميق.
- البناء المحلي ولّد 201 صفحة محتوى مُسبق، وفحص بوابة SEO المحلي اجتاز تعارضات الخريطة والـ `noindex` والروابط القديمة.

لكن توجد مشكلة **حرجة P0**:

> `https://alsahmm.com/sitemap.xml` متاح كملف XML من حيث نوع الاستجابة، لكن كل روابط `<loc>` داخله مكسورة: مثل `http:` و`http:/about` بدلاً من `https://alsahmm.com/` و`https://alsahmm.com/about`.

هذا يعني أن Google يستطيع العثور على ملف الخريطة لكنه لا يستطيع استخدام عناوينه للوصول إلى الصفحات. إصلاح هذه النقطة وإعادة إرسال الخريطة في Google Search Console هو الأولوية قبل أي تحسين محتوى إضافي.

## الأدلة التي تم التحقق منها

### 1. قابلية الزحف والأرشفة

- الصفحة الرئيسية الحية:
  - `200 OK`
  - حجم HTML يقارب 73.8KB
  - عنوان واحد، وصف واحد، `H1` واحد، و`canonical` صحيح.
- صفحات الخدمات والأحياء والمقالات تعيد HTML مسبق البناء، وليس `#root` فارغاً ينتظر JavaScript.
- الفحص العميق لـ 24 مساراً أعاد `200/24`.
- `robots.txt` الحي:
  - `User-agent: *`
  - `Allow: /`
  - حظر `/admin/` و`/api/`
  - يشير إلى `https://alsahmm.com/sitemap.xml`
  - يسمح لروبوتات البحث بالوصول إلى المحتوى العام.
- لا يوجد في الصفحات العامة المفحوصة `noindex`.

### 2. الخريطة الحية — المشكلة الحرجة

الاستجابة الحية تعيد:

- `Content-Type: application/xml`
- `200 OK`
- 152 وسم `<loc>`

لكن أول الروابط الفعلية هي:

```xml
<loc>http:</loc>
<loc>http:/about</loc>
<loc>http:/pricing</loc>
<loc>http:/services</loc>
```

بينما الخريطة المحلية الموجودة في المشروع تبدأ بشكل صحيح:

```xml
<loc>https://alsahmm.com/</loc>
<loc>https://alsahmm.com/about</loc>
<loc>https://alsahmm.com/pricing</loc>
<loc>https://alsahmm.com/services</loc>
```

**الاستنتاج:** الخلل في النسخة المنشورة أو في آخر عملية توليد/حفظ للخريطة، وليس في ملف الخريطة المحلي الحالي. لا ينبغي اعتبار وجود `200` أو نوع XML دليلاً على صحة الخريطة؛ محتوى `<loc>` نفسه يجب التحقق منه.

### 3. عناصر الصفحة الأساسية

من الصفحات الحية المفحوصة:

| الصفحة | العنوان | طول الوصف | Canonical | H1 |
|---|---|---:|---|---:|
| `/` | موجود | 140 | صحيح | 1 |
| `/services` | موجود | 149 | صحيح | 1 |
| `/about` | موجود | 126 | صحيح | 1 |
| `/contact` | موجود | 112 | صحيح | 1 |
| `/blog` | موجود | 140 | صحيح | 1 |
| `/faq` | موجود | 129 | صحيح | 1 |
| `/cleaning-packages` | موجود | 114 | صحيح | 1 |
| `/areas` | موجود | 103 | صحيح | 1 |
| `/privacy` | موجود | 121 | صحيح | 1 |
| `/terms` | موجود | 105 | صحيح | 1 |

المسارات التي تحتوي على شرطة نهائية تُوحّد نفسها عبر `canonical` إلى النسخة غير المنتهية، مثل:

```text
/about/ → https://alsahmm.com/about
/blog/ → https://alsahmm.com/blog
/services/tanzeef-filal-alryad/ → https://alsahmm.com/services/tanzeef-filal-alryad
```

هذا جيد ويقلل الازدواجية، مع ضرورة الحفاظ على نفس السياسة في كل المسارات الجديدة.

### 4. Open Graph وTwitter

الصفحة الرئيسية والصفحات الرئيسية تحتوي على:

- `og:title`
- `og:description`
- `og:url`
- `og:type`
- `og:locale`
- `og:site_name`
- `og:image`
- Twitter Card

**ملاحظة متوسطة:** صفحة `/blog` تستخدم في النسخة الحية:

```html
<meta property="og:image" content="/images/service-facades.jpg">
<meta name="twitter:image" content="/images/service-facades.jpg">
```

الأفضل تحويلها إلى رابط مطلق:

```text
https://alsahmm.com/images/service-facades.jpg
```

لضمان ثبات المعاينة عند مشاركة الرابط عبر كل المنصات والروبوتات.

### 5. البيانات المنظمة Schema

الصفحة الرئيسية تحتوي على أربعة كتل JSON-LD صالحة في الفحص، وظهر فيها:

- `LocalBusiness` / `HousekeepingService`
- `WebSite`
- `FAQPage`
- تقييم مجمع
- `hasOfferCatalog` مع 15 عرضاً في الفحص الحي.

كما ظهرت `BreadcrumbList` في صفحات مثل:

- `/about`
- `/contact`
- `/blog`
- `/faq`
- `/areas`

وصفحات الخدمات والمقالات تحتوي على بيانات نوع الخدمة/المقالة والأسئلة الشائعة بحسب المحتوى.

**تنبيه:** وجود Schema لا يضمن ظهور rich results؛ يجب اختبار الصفحات المهمة لاحقاً عبر Rich Results Test، خصوصاً بعد أي تعديل على البيانات أو التقييمات.

### 6. المحتوى والربط الداخلي

الإيجابيات:

- توجد صفحات خدمات، باقات، أحياء، مدونة، أسئلة شائعة، ومقالات طويلة، وهذا يعطي تغطية جيدة لنية البحث المحلية.
- فحص الروابط السياقية وجد أن 34/34 مقالاً في قاعدة البيانات تحتوي على روابط داخلية إلى الخدمات أو المناطق.
- صفحة المدونة الحية تحتوي على عدد كبير من الروابط الداخلية وعناوين مقالات واضحة.
- صفحات المقالات تحتوي على صندوق روابط للخدمات ذات الصلة.

التحسينات المطلوبة:

- فحص صفحة حي الملقا في النسخة الحية لم يجد روابط مباشرة للخدمات داخل HTML الخام، رغم وجود روابط للمناطق المجاورة. يجب ربط كل صفحة حي بخدمتين أو ثلاث خدمات ذات صلة، مثل تنظيف الفلل أو المجالس أو ما بعد البناء.
- فحص صفحة حي الملقا لم يجد بروفايل محلياً أو أسئلة شائعة مخصصة للحي. صفحات الأحياء التي تكرر قالباً عاماً دون تفاصيل حقيقية قد تُعامل كمحتوى ضعيف أو متشابه.
- فحص صفحة خدمة الفلل وجد FAQ وCTA، لكنه لم يلتقط بنية واضحة لخطوات التنفيذ. إضافة خطوات عملية حقيقية ومخصصة للخدمة ستقوي نية البحث وتقلل تشابه الصفحات.
- بوابة SEO المحلية أعطت تحذيرات لغياب CTA واضح في `/about` و`/blog` وبعض صفحات السياسات/الباقات. وجود رابط واضح مثل “اطلب الخدمة” أو “تواصل عبر واتساب” في الصفحات التجارية أفضل من الاعتماد على القائمة العامة فقط.

### 7. الصور

- الصور المفحوصة في الصفحات الحية التي تحتوي على `<img>` لديها `alt`.
- أغلب الصور تستخدم WebP أو صيغاً حديثة، مع وجود بعض JPGs في الأصول.
- يجب التأكد من أن كل صور `og:image` و`image sitemap` روابط مطلقة وموجودة فعلياً بعد كل نشر.

### 8. الأداء والاستضافة

المشروع يستخدم البناء المسبق والصور الحديثة، وهذا جيد نظرياً. لكن لا يمكن إثبات Core Web Vitals من فحص HTML وحده.

يجب تشغيل PageSpeed Insights أو Lighthouse على الأقل على:

1. الصفحة الرئيسية.
2. صفحة خدمة رئيسية.
3. صفحة حي.
4. صفحة مقال.

المقاييس المستهدفة:

- LCP أقل من 2.5 ثانية.
- INP أقل من 200ms.
- CLS أقل من 0.1.

الاستجابة الحية لا تُظهر حالياً ترويسة HSTS، لذلك يجب مراجعة إعداد HTTPS/Headers في Hostinger. هذا ليس سبباً مباشراً لخلل الخريطة، لكنه تحسين أمني وتقني مستحسن.

## خطة الإصلاح حسب الأولوية

### P0 — قبل أي تحسين آخر

1. إصلاح `sitemap.xml` المنشور بحيث تكون كل `<loc>` روابط مطلقة تبدأ بـ `https://alsahmm.com`.
2. التحقق آلياً من:
   - عدد الروابط.
   - عدم وجود `http:` أو `http:/`.
   - عدم وجود `localhost` أو نطاق Replit.
   - عدم وجود روابط مكررة.
   - أن كل رابط يعيد `200` وCanonical متوافقاً.
3. إعادة إرسال الخريطة في Google Search Console.
4. فحص Google Search Console بعد 24–72 ساعة للتأكد من زوال أخطاء الخريطة.

### P1 — تحسينات ذات أثر مرتفع

1. تحويل صورة Open Graph في `/blog` وأي صفحة أخرى من مسار نسبي إلى URL مطلق.
2. إضافة روابط خدمات مباشرة داخل صفحات الأحياء.
3. إضافة تفاصيل محلية أصلية لكل حي: نوع العقارات، حالات الاستخدام، نطاق الخدمة، وFAQ خاص بالحي، دون نسخ نفس النص.
4. وضع CTA تجاري واضح في صفحة المدونة وصفحة من نحن.
5. اختبار JSON-LD عبر Rich Results Test، خصوصاً `LocalBusiness`, `FAQPage`, `Article`, و`BreadcrumbList`.

### P2 — تحسينات النمو والمراقبة

1. ربط Google Business Profile بالاسم والعنوان والهاتف نفسه الظاهر في الموقع.
2. توحيد بيانات NAP في الموقع وملف النشاط التجاري والمنصات الخارجية.
3. إضافة `dateModified` حقيقي ومحدث في المقالات والصفحات التي تتغير.
4. تشغيل Lighthouse/PageSpeed وتسجيل النتائج قبل وبعد التحسين.
5. تحديث فحص الروابط المحلي حتى لا يتوقف عند قاعدة البيانات الثانوية القديمة؛ الفحص الحالي نجح على قاعدة البيانات الرئيسية ثم فشل عند قاعدة ثانوية لا تحتوي جدول `posts`.

## نتيجة فحوص البناء المحلي

- بناء Vite اكتمل بنجاح بعد تحويل 3801 وحدة.
- ظهرت تحذيرات sourcemap غير مانعة في بعض مكونات الواجهة.
- `prerender.mjs` ولّد:
  - 34 مقالاً.
  - 15 خدمة.
  - 15 باقة.
  - 85 صفحة SEO.
  - 50 صفحة حي.
  - صفحات المحاور والسياسات والأسعار والأسئلة الشائعة.
- الناتج أعلن 201 صفحة HTML مسبقة، وفحص بوابة SEO وجد 352 ملف HTML بسبب المسارات البديلة/المحاور.
- بوابة SEO اجتازت:
  - عدم وجود روابط محلية.
  - عدم وجود روابط package/container قديمة في الخريطة المحلية.
  - عدم وجود تعارضات noindex مع الخريطة.
  - وجود title وcanonical وH1 في ملفات HTML المفحوصة.
- فحص `check-links.mjs` لم يكتمل لأنه يحاول أيضاً قراءة قاعدة بيانات ثانوية لا تحتوي جدول `posts`. هذه مشكلة في أداة الفحص وليست دليلاً على فقدان المقالات من الموقع.

## الرد الجاهز للوكيل السابق

> أكملت تدقيق SEO من نقطة التوقف، وهذه النتيجة الدقيقة:
>
> الأساس التقني للموقع جيد: الصفحات العامة مُسبقة البناء وتظهر HTML فعلياً للزاحف، والعناوين والأوصاف وCanonical وH1 موجودة، و`robots.txt` صحيح، والصفحة الرئيسية تحتوي LocalBusiness وWebSite وFAQ وOfferCatalog وتقييماً منظماً. الفحص الحي اختبر 24 مساراً وجميعها أعادت 200، والبناء المحلي اجتاز بوابة SEO وولّد تغطية واسعة للمقالات والخدمات والباقات والأحياء.
>
> لكن اكتشفت مشكلة حرجة في النشر: `https://alsahmm.com/sitemap.xml` يرجع XML بحالة 200، إلا أن كل روابط `<loc>` داخله مكسورة مثل `http:` و`http:/about` بدلاً من `https://alsahmm.com/...`. الخريطة المحلية الحالية صحيحة، لذلك الخلل في النسخة المنشورة أو آخر عملية توليد/حفظ لها. يجب إصلاح الخريطة وإعادة نشرها ثم إرسالها في Search Console قبل أي تحسينات أخرى.
>
> توجد تحسينات P1 بعدها: جعل صورة OG في `/blog` مطلقة، إضافة روابط الخدمات داخل صفحات الأحياء، كتابة تفاصيل وFAQ أصلية لكل حي، وإضافة CTA واضح في `/about` و`/blog`. كما أن أداة `check-links.mjs` تحتاج معالجة القاعدة الثانوية القديمة لأنها تتوقف عند جدول `posts` المفقود.

## Remediation / Post-Audit

### ما كان ناقصاً من التنفيذ السابق

كان توحيد الرابط الأساسي قد طُبق في prerender وطبقة PHP وواجهة API، لكن مولد sitemap المحلي لم يكن يستخدم نفس المصدر المركزي، ولم تكن هناك بوابة مستقلة تتحقق من صحة كل `<loc>` قبل تغليف أرشيف Hostinger. كما أن فحص الروابط كان يتعامل مع قاعدة البيانات الثانوية القديمة كأنها خطأ في الموقع.

### ما تم استكماله

- جعل مولد sitemap المحلي يستخدم `scripts/seo-config.mjs` ومصدر الإنتاج الثابت `https://alsahmm.com` بدلاً من قيمة قاعدة بيانات أو متغير بيئة غير مضمون.
- إضافة `scripts/validate-sitemap.mjs` للتحقق من XML، والروابط المطلقة، وHTTPS، والمضيف الصحيح، والروابط المحلية/المعاينة، والتكرار، ومسارات الإدارة وAPI، مع فصل ERROR عن WARNING وINFO.
- ربط التحقق بمسار `build-hostinger.mjs` مرتين: بعد إنشاء sitemap المصدر وبعد إنشاء sitemap النهائي داخل الأرشيف، ثم تشغيل بوابة SEO على HTML المسبق.
- جعل صورة Open Graph لصفحة المدونة، وجميع صور OG التي يمررها prerender، روابط مطلقة.
- منع واجهة canonical من قبول مضيف بديل أو `www` أو `http` من إعدادات الموقع؛ السياسة المعتمدة هي `https://alsahmm.com`.
- جعل `check-links.mjs` يتجاوز قاعدة البيانات الثانوية الاختيارية التي لا تحتوي جدول `posts` مع تصنيفها كتحذير أداة، مع تصحيح شرط الروابط نفسه.

### الملفات التي تغيرت وسبب التغيير

| الملف | السبب |
|---|---|
| `scripts/seo-config.mjs` و`generate-sitemap.mjs` | ضمان مصدر إنتاج واحد لمولد sitemap |
| `scripts/validate-sitemap.mjs` | منع تغليف sitemap غير صالحة |
| `scripts/seo-quality-gate.mjs` | استخدام المدقق ضمن فحص البناء |
| `scripts/build-hostinger.mjs` | ترتيب Generate → Validate → Build → Validate |
| `scripts/prerender.mjs` | تثبيت روابط OG المطلقة |
| `artifacts/sabaik-almasa/src/lib/siteUrl.ts` | تثبيت سياسة canonical على المضيف الرسمي |
| `artifacts/api-server/src/routes/sitemap.ts` | إزالة مسار host غير الموثوق من مولد API |
| `scripts/check-links.mjs` | فصل خطأ الأداة عن خطأ الموقع |
| `scripts/package.json` | توفير أمر تحقق مستقل |

### نتائج الاختبارات والتحقق

- تم فحص `https://alsahmm.com/sitemap.xml` مباشرة: `200 OK` و`Content-Type: application/xml`.
- الروابط الأولى في النسخة الحية وقت الفحص كانت `https://alsahmm.com/...`، ولم تعد بصيغة `http:` أو `http:/...`.
- تم تشغيل تحقق محلي مستقل على sitemap المصدر وعلى sitemap الأرشيف بعد البناء.
- تم تشغيل بوابة SEO على HTML المسبق، مع إبقاء التحذيرات غير المانعة منفصلة عن أخطاء البناء.
- تم تعديل فحص الروابط بحيث لا يتوقف بسبب قاعدة ثانوية قديمة لا تحتوي جدول `posts`.

### ما تم التحقق منه في Production وما لم يمكن التحقق منه

تم التحقق من استجابة sitemap الحية ومضيف الروابط ومخططها وقت الفحص. لم يتم تنفيذ نشر جديد من هذه الجولة، لذلك لا يمكن اعتبار النسخة الجديدة من الأرشيف منشورة حتى يتم رفعها إلى Hostinger. كما لم يتم حسم Core Web Vitals أو اختبار Rich Results من داخل البناء المحلي.

### المشاكل المتبقية والتوصيات
